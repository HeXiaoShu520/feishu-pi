## 1. 使用的系统与工具

本项目采用 **Node.js ESM + TypeScript** 技术栈，依赖管理完全基于 **npm**：
- 包清单与版本声明：`package.json`
- 锁定文件：`package-lock.json`（由 npm 生成，用于固定所有传递依赖的精确版本）
- 运行时类型定义：通过 `@types/*` 包在 `devDependencies` 中声明
- 构建/运行工具链：`tsx`（TypeScript 直接执行）、`typescript`、`vitest`、`vite` 均作为开发依赖
- 无私有 npm registry 配置，无 `.npmrc`，无 `pnpm`/`yarn`/`bun` 痕迹，统一使用 `npm install`。

项目根目录存在 `node_modules/` 与 `package-lock.json`，表明依赖以常规方式安装到本地模块目录，未使用 vendoring 或 lockfile-only 策略。

## 2. 关键文件与依赖范围

- `package.json`：声明了生产依赖与开发依赖两个层次。
  - 生产依赖包括飞书 Pi Agent 生态包（`@earendil-works/pi-agent-core`、`@earendil-works/pi-ai`、`@earendil-works/pi-coding-agent`，版本 `^0.84.2`）、飞书官方 SDK（`@larksuiteoapi/node-sdk` `1.73.0`）、HTTP 框架（`express` `^5.2.1`、`body-parser` `^2.3.0`）、调度器（`croner` `^10.0.1`）与环境变量加载（`dotenv` `^17.4.2`）。
  - 开发依赖包含 TypeScript 5.9.3、`tsx` 4.22.1、Vitest 3.x、Vite 6.x 以及 Node 类型定义。
- `tsconfig.json`：将 `moduleResolution` 设为 `NodeNext`，配合 `"type": "module"`，确保依赖解析遵循 ESM 语义。
- `scripts/patch-pi-ai.js`：`postinstall` 钩子脚本，在 `npm install` 后自动修补第三方库。
- `README.md`：明确文档化“环境要求 Node.js 22+，包管理器为 npm”，并说明 `npm install` 会触发 `postinstall` 打补丁。

## 3. 架构与约定

### 3.1 版本策略
- 生产依赖主要使用 **caret 范围**（如 `^0.84.2`、`^5.2.1`），允许小版本升级；少数核心依赖（如 `@larksuiteoapi/node-sdk`）使用**精确版本**（`1.73.0`）以避免破坏性变更。
- 通过 `package-lock.json` 锁定所有传递依赖的完整树，保证不同环境安装结果一致。
- 项目标记为 `private: true`，不发布到 npm registry。

### 3.2 postinstall 补丁机制
项目通过 `package.json.scripts.postinstall` 调用 `node scripts/patch-pi-ai.js`，在每次 `npm install` 后对 `node_modules/@earendil-works/pi-ai/dist/api/anthropic-messages.js` 进行文本级替换，删除请求头 `anthropic-dangerous-direct-browser-access: true`，以规避经 API 中转站调用时返回 403 的问题。该脚本具备容错设计：若目标文件不存在（例如上游升级导致路径变化），仅输出警告而不中断安装流程。

此机制是本项目依赖管理的核心扩展点——它在不 fork 上游仓库的前提下，解决了第三方包的运行时兼容性问题，并在每次重装依赖时自动重新应用。

### 3.3 类型与运行时解耦
- 类型定义（`@types/body-parser`、`@types/express`、`@types/node`）放在 `devDependencies`，不影响生产产物。
- `tsconfig.json` 设置 `skipLibCheck: true`，避免第三方库的类型差异阻塞编译。

## 4. 约定与约束

- **包管理器约定**：README 明确要求使用 `npm` 作为唯一包管理器；项目中未见 `.npmrc`、`.yarnrc`、`pnpm-lock.yaml` 等替代工具配置。
- **安装即补丁**：`npm install` 必须成功完成 `postinstall` 才能正常使用；任何绕过 `npm install` 的行为（如手动复制 `node_modules`）会导致补丁缺失。
- **依赖升级风险**：由于 `patch-pi-ai.js` 硬编码了 `@earendil-works/pi-ai` 的 dist 路径，升级该包时需验证补丁脚本是否仍匹配；当前脚本已内置异常捕获，不会阻断安装，但可能静默失效。
- **无私有源**：未发现任何 npm registry 重定向、token 或代理配置，依赖全部来自公共 npm registry。
- **ESM 优先**：`"type": "module"` 与 `NodeNext` 模块解析策略意味着依赖需支持 ESM 入口，否则可能出现运行时导入失败。
