## 1. 采用的方案

本项目采用 **纯环境变量 + 本地 `.env` 文件** 的配置方式，核心入口通过 `dotenv/config` 在进程启动时自动加载 `.env`，再由 `src/config.ts` 中的 `loadConfig()` 统一解析为强类型 `FeishuPiAppConfig` 对象。此外，项目还内置了一个基于 Express 的本地配置页面（`src/config-server.ts`），运行于 `127.0.0.1:3456`，提供对 `.env` 文件的读取与保存能力，方便开发者在浏览器中编辑配置。

## 2. 关键文件

- `src/config.ts`：定义 `FeishuPiAppConfig` 接口与 `loadConfig(env)` 函数，负责从 `process.env` 读取并校验所有运行时配置。
- `src/utils/env-file.ts`：纯函数实现的 `.env` 文件解析/序列化工具，供配置页面使用；维护 `MANAGED_KEYS` 白名单，声明表单可管理的键集合。
- `src/config-server.ts`：Express 应用，监听 `127.0.0.1:3456`，暴露 `/`、`/api/config`、`/stats`、`/api/stats/events` 等路由，读写根目录 `.env`。
- `src/main.ts`：进程入口，调用 `dotenv/config` 加载 `.env`，调用 `loadConfig()` 获取配置，并组装运行时、传输层、权限策略、定时任务等组件。
- `.env.example`：示例环境变量清单，覆盖飞书凭据、模型配置、审核接口、组成员归属、授权超时等全部可选/必填项。

## 3. 架构与设计约定

### 3.1 配置来源与优先级

- 唯一持久化源：项目根目录的 `.env` 文件。
- 运行时注入：`loadConfig()` 接受 `NodeJS.ProcessEnv` 参数（默认 `process.env`），便于测试时注入模拟环境。
- 默认值策略：非必填字段提供合理默认值（如 `FEISHU_PI_MODEL_PROVIDER=anthropic`、`FEISHU_PI_MODEL_NAME=claude-sonnet-4-6`、`guardTimeoutMs=15000`、`approvalTimeoutMs=300000`），缺失则回退到默认或空值。
- 必填校验：通过内部 `required(name)` 辅助函数，缺失 `FEISHU_APP_ID`、`FEISHU_APP_SECRET` 等必填变量时直接抛错，阻止服务启动。

### 3.2 配置分组与环境变量命名规范

所有配置均以 `FEISHU_*` / `FEISHU_PI_*` / `FEISHU_GUARD_*` 前缀区分用途：
- 飞书凭据：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_ADMIN`。
- Agent 工作目录：`FEISHU_PI_CWD`（留空时使用 `process.cwd()`）。
- 模型配置：`FEISHU_PI_MODEL_PROVIDER`、`FEISHU_PI_MODEL_NAME`、`FEISHU_PI_MODEL_BASE_URL`、`FEISHU_PI_MODEL_API_KEY`、`FEISHU_PI_SYSTEM_PROMPT`。
- 审核（Guard）：`FEISHU_GUARD_BASE_URL`、`FEISHU_GUARD_MODELS`（逗号分隔）、`FEISHU_GUARD_API_KEY`（回退到 `FEISHU_PI_MODEL_API_KEY`）、`FEISHU_GUARD_TIMEOUT_MS`。
- 权限分组：动态前缀 `FEISHU_GROUP_<NAME>`，值为逗号分隔的成员列表，由 `loadConfig()` 扫描 `process.env` 中所有以 `FEISHU_GROUP_` 开头的键并构建 `groupMembership` 映射。
- 授权超时：`FEISHU_APPROVAL_TIMEOUT_MS`。

### 3.3 配置文件格式与保留策略

`src/utils/env-file.ts` 实现轻量级 `.env` 解析器：忽略注释行（`#` 开头）和无 `=` 的行；`stringifyEnv()` 按固定顺序输出飞书凭据、随机表情、模型配置、API Key、系统提示词，并将不属于 `MANAGED_KEYS` 的已有键（如 `FEISHU_GUARD_*`、`FEISHU_GROUP_*`、`FEISHU_APPROVAL_TIMEOUT_MS`）原样追加到末尾，确保通过 Web 表单编辑时不会丢失手工配置。

### 3.4 配置页面的安全约束

- 仅绑定 `127.0.0.1`，不暴露到局域网（代码注释明确说明“接口明文返回 App Secret，不能暴露到局域网”）。
- 端口固定为 `3456`。
- 读取/写入的是项目根目录下的 `.env` 文件。

### 3.5 废弃配置的兼容处理

`FEISHU_CMD_WHITELIST` 已标记为废弃，`loadConfig()` 仍会解析该变量但仅用于启动时打印弃用警告，实际工具规则迁移至 `.agent/permissions.json` 的 `permissions.allow` 字段（见 `src/main.ts` 中对 `cmdWhitelist.length > 0` 的 warn 日志）。

## 4. 约定与约束

- **必填变量**：`FEISHU_APP_ID`、`FEISHU_APP_SECRET` 必须存在，否则 `loadConfig()` 抛出错误终止启动。
- **管理员自动归属**：`FEISHU_ADMIN` 自动加入 `owner` 组（见 `.env.example` 注释），无需显式声明。
- **组名大小写不敏感**：`FEISHU_GROUP_<NAME>` 解析时将组名转为小写（`key.slice(...).toLowerCase()`）。
- **多模型审核取交集**：`FEISHU_GUARD_MODELS` 支持逗号分隔多个模型，语义为“全部 allow 才放行，任一 ask 即弹卡”。
- **Guard API Key 回退**：若未配置 `FEISHU_GUARD_API_KEY`，则回退使用 `FEISHU_PI_MODEL_API_KEY`。
- **会话数据路径固定**：`sessionDir` 固定为 `${process.cwd()}/data/sessions`，图片缓存位于 `images/`，消息存储位于 `messages.json`。
- **策略文件路径**：权限策略文件固定位于 `<cwd>/.agent/permissions.json`，由 `PermissionPolicy` 加载。
- **配置变更热生效**：模型切换通过 transport 回调 `onModelSwitch` 触发 `runtime.setModelName()`，配合配置页修改 `.env` 后重启即可生效。

## 5. 适用性判断

本仓库存在完整且结构清晰的配置系统：统一的 `.env` 驱动、类型化的配置加载、Web 配置页、环境变量命名规范、废弃兼容处理等，因此该类别完全适用。
