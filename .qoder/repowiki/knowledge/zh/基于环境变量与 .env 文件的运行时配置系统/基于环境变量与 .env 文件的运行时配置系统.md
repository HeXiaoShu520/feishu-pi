## 1. 采用的系统与方案

本项目采用**纯环境变量 + `.env` 文件**的配置方式，未引入 YAML/TOML/JSON 等结构化配置文件。核心依赖 `dotenv`（通过 `import "dotenv/config"` 在入口自动加载），并通过一个自研的轻量 Web 管理界面（Express，监听 `127.0.0.1:3456`）对 `.env` 进行读取、编辑与持久化。

## 2. 关键文件与包

- `src/config.ts`：定义 `FeishuPiAppConfig` 接口与 `loadConfig()` 解析函数，是所有运行期配置的单一入口。
- `src/utils/env-file.ts`：`.env` 文件的纯解析/序列化/单键更新工具（无副作用，可单测），维护 `MANAGED_KEYS` 白名单以区分“表单管理的键”和“手工保留的键”。
- `src/config-server.ts`：本地 Express 服务，提供 `/api/config`（GET/POST）读写 `.env`，以及 `/stats` 统计页面；仅绑定 `127.0.0.1`，避免暴露敏感配置。
- `src/main.ts`：应用启动入口，调用 `loadConfig()` 装配所有模块，并注册配置页路由。
- `.env.example`：示例环境变量清单。
- `package.json`：脚本 `start`/`dev` 通过 `tsx src/main.ts` 启动，`config` 脚本直接运行配置页。

## 3. 架构与约定

### 3.1 配置加载顺序
1. 进程启动时 `dotenv/config` 自动将 `.env` 注入 `process.env`。
2. `main()` 调用 `loadConfig(env = process.env)` 统一解析，返回强类型 `FeishuPiAppConfig`。
3. 各模块（飞书 Client、PermissionPolicy、ToolGuard、ScheduleService、ConversationStore 等）从该配置对象取所需字段，不再直接读 `process.env`。

### 3.2 配置项分层
- **必填凭据**：`FEISHU_APP_ID`、`FEISHU_APP_SECRET`，缺失时 `required()` 抛出错误阻止启动。
- **模型配置**：`FEISHU_PI_MODEL_PROVIDER`（默认 `anthropic`）、`FEISHU_PI_MODEL_NAME`（默认 `claude-sonnet-4-6`）、`FEISHU_PI_MODEL_BASE_URL`、`FEISHU_PI_MODEL_API_KEY`、`FEISHU_PI_SYSTEM_PROMPT`。
- **权限与分组**：`FEISHU_ADMIN`（管理员标识）+ 动态前缀 `FEISHU_GROUP_<NAME>=成员1,成员2,...`，由 `loadConfig` 扫描所有以 `FEISHU_GROUP_` 开头的变量构建 `groupMembership`。
- **审核/闸门**：`FEISHU_GUARD_BASE_URL`、`FEISHU_GUARD_MODELS`（逗号分隔）、`FEISHU_GUARD_API_KEY`（回退到 `FEISHU_PI_MODEL_API_KEY`）、`FEISHU_GUARD_TIMEOUT_MS`（默认 15s）。
- **交互行为**：`FEISHU_APPROVAL_TIMEOUT_MS`（默认 5 分钟）、`FEISHU_SHOW_MODEL_STATS`（布尔开关，支持 `1/true/on/yes`）。
- **路径**：`cwd`（默认 `process.cwd()`）、`sessionDir`（固定 `${cwd}/data/sessions`）、`dataDir`（固定 `${cwd}/data`）。
- **已废弃但兼容**：`FEISHU_CMD_WHITELIST` 仍被解析并在启动时输出弃用警告，规则迁移至 `.agent/permissions.json`。

### 3.3 运行时热更新机制
- 配置页通过 `stringifyEnv(config, existing)` 写回 `.env`，其中 `existing` 来自当前 `.env` 解析结果；不属于 `MANAGED_KEYS` 的键（如 `FEISHU_GUARD_*`、`FEISHU_GROUP_*`、`FEISHU_APPROVAL_TIMEOUT_MS`）会被原样追加，保证手工配置不丢失。
- 单个键值对可通过 `upsertEnvLine(content, key, value)` 原位替换或追加，供 `/model` 等指令在运行期切换模型。
- 模型切换还通过 `onModelSwitch` 回调通知 `LarkTransport`，进而调用 `runtime.setModelName(name)` 实现热切换。

### 3.4 配置页安全约束
- 服务仅监听 `127.0.0.1:3456`，注释明确说明“接口明文返回 App Secret，不能暴露到局域网”。
- 配置页 HTML 与统计页 HTML 作为静态资源内嵌读取，避免额外请求。

## 4. 约定与约束

| 约定 | 来源/依据 |
|---|---|
| 必需环境变量缺失时启动即抛错 | `src/config.ts` 中 `required()` 的实现 |
| 布尔型开关统一使用 `parseBoolEnv`，接受 `1/true/on/yes`（大小写不敏感） | `src/config.ts` |
| 组归属关系通过 `FEISHU_GROUP_<NAME>` 动态前缀声明，组名小写化 | `src/config.ts` 解析逻辑 |
| 表单管理的键集中在 `MANAGED_KEYS` 集合，不在其中的键保存时原样保留 | `src/utils/env-file.ts` |
| 已废弃的 `FEISHU_CMD_WHITELIST` 仍解析但启动时打印弃用警告 | `src/config.ts` + `src/main.ts` |
| 配置页仅本机访问（`127.0.0.1`） | `src/config-server.ts` 的 `app.listen` 参数与注释 |
| 会话目录、数据目录路径固定为 `${cwd}/data/sessions` 与 `${cwd}/data` | `src/config.ts` |
| 模型 API Key 同时用于主模型与审核（guard）API，后者可独立覆盖 | `src/config.ts` 中 `guardApiKey` 的回退逻辑 |

## 5. 测试覆盖

- `test/config.test.ts`：验证 `loadConfig` 的行为。
- `test/env-file.test.ts`：验证 `.env` 解析、序列化与单键更新的正确性。

## 6. 总结

本项目的配置系统以**环境变量为唯一事实源**，通过 `loadConfig` 集中解析并强类型化，配合本地 Web 管理界面完成可视化编辑与持久化。它没有引入外部配置格式，而是围绕 `.env` 文件构建了一套轻量、可热更新的配置管线，并通过 `MANAGED_KEYS` 白名单机制平衡了“表单易用性”和“手工配置保留”的需求。
