# 流程转脚本（Skill → Script）

当一个流程已经固化（步骤固定、高频使用、需要授权边界），把它从"说明书"升级为"脚本能力"。

## 为什么转

技能是公开的说明书：藏不住、挡不住，AI 照样能按它模拟执行。**脚本才有授权边界**——策略文件里把脚本名加进某个组的 `tools` 名单，能力才真正可控。

## 什么时候不转

判断型工作（代码审查、调试分析、需求讨论）留在技能里——每一步取决于现场情况，转成脚本反而僵化。

## 转换步骤

### 1. 读取并分析技能

读取 `.agent/skills/{name}.md`，提炼：
- 固定的步骤序列
- 变化的输入（哪些是参数、哪些是常量）
- 外部依赖（命令、API、文件路径）

### 2. 编写脚本

写入 `.agent/scripts/{name}.ts`，文件即工具：

```typescript
// description: 一句话说明用途（模型据此决定何时调用）
// input: {"target": "目标参数"}     （可选，参数示例）

const input = JSON.parse(process.argv[2] ?? "{}");
// 固化流程：校验参数 → 执行 → console.log 输出结果
console.log("完成");
```

要点：
- **变化的做成参数（argv JSON），固定的写进代码**——参数越少越安全
- 结果 `console.log` 输出；失败往 stderr 打印并以非零退出
- 运行有 30 秒超时；逻辑复杂/耗时长时优先拆分

### 3. 策略授权

在 `.agent/permissions.json` 中，把脚本名加进目标组的 `tools` 名单：

```json
{ "user": { "tools": ["my-name"] } }
```

名单外的人无法调用（脚本不进其会话）。

### 4. 收尾

- 与用户确认效果，必要时删除原技能文件（能力已收进脚本，说明书可留可删）
- 新会话生效（`/new`）
