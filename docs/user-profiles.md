# AI内部用户画像

画像属于 AI 对每个人逐步积累的内部记忆资料，不是用户可填写、查看或直接编辑的个人档案。不提供 `/profile` 命令、增删改接口或普通用户资料管理工具。

## 已预留的结构

`src/memory/profile.ts` 把有原话依据的用户记忆按偏好、相处边界、自述背景、共同话题与经历分组，每项保留主题、内容、依据、更新时间和“未经独立核实”的来源说明。`MemoryService.profile(openId, context)` 是仅供宿主代码使用的内部视图，没有注册为模型工具或飞书接口，不额外保存一份可能漂移的总结文件。

正式运行使用 `userUpdates: agent`：聊天 AI 自己判断必要时调用内部 `profile_update` 能力，新增、纠正或删除某个用户条目。普通闲聊不自动写用户画像，不要求用户填写或确认。工具使用策略只在工具 description 中提供，不进入静态人格提示。

该能力由运行时绑定当前发言人的 openId、聊天与话题，以及本轮 `memoryText` 原文；工具参数不能选择目标人、路径或会话。画像按当前发言人 openId 保存，跨聊天共用。证据必须逐字匹配本轮本人原话，离开该轮或中断后不能再用。remember 沿用同主题纠正；forget 只作用于当前用户的画像条目，不能删除其他人的资料或助手自我视角条目。调用仍受 permissions.json 和审核门禁控制；访客仅额外开放宿主创建的安全画像工具，不开放任何本地或管理员工具。

用户画像保存于 `data/agent-memory/v2/user-<用户ID哈希>.json`，仅按 openId 区分。同一个人在私聊、不同群和话题共用一份画像；不同人的画像隔离。聊天时继续只召回相关条目（含 id 和主题），不注入整份画像。画像写入按人串行化，原子替换；损坏文件不会被覆盖。关闭 `FEISHU_PI_AGENT_MEMORY` 时不注册画像能力。正常交流中出现明确更正时由 AI 决定调用更新，主程序不再把后台提炼出的用户条目自动写回。

助手自我视角 interest/viewpoint/thread 的有来源后台提炼仍按原方式运行，最多60秒节流；与用户画像的自主更新分开。`automatic` 模式仅保留给记忆提炼评测与兼容调用，正式 main.ts 显式选择 agent 模式。

主人身份由可信账号配置确认，画像不授予权限。不会自动把短回复、单次玩笑推断为固定性格，也不做心理诊断或好感打分。第三人的评论不能作为当前用户自述事实，助手自我视角资料不混入用户画像。

未启用全历史批量扫描、群聊旁听建档或性格报告导入。未来若增加暂定印象，需独立区分观察与事实，保留多轮依据、允许修正和过期，不得把推测写成确定人格。群聊观察预留见 [group-impressions.md](group-impressions.md)。


## 实际验证

2026-11-15 使用本机 deepseek-flash 做隔离会话评测，无飞书发送：普通“你好呀”没有调用画像工具；“我平常聊天喜欢短一点的回复，不喜欢被连续追问。”在复测中自主调用 profile_update 并实际落盘，回复没有附加画像汇报。明确要求以后记住的场景也成功落盘，一次参数 JSON 错误后模型自行重试成功。更早的一轮隐含偏好没有触发调用，说明模型自主判断仍可能漏记，不能保证每次识别所有值得保存的信息；主程序不再以后台强制写入掩盖这一点。评测记录见 data/profile-evals/2e87d3ed-d96d-43a8-91aa-b0a0896d35a9/report.json。


## 按人保存（2026-11-16）

新画像只按飞书 openId 保存，不按聊天类型、chatId或话题拆分。同一应用下同一个人的稳定用户 ID 在各聊天中共用；改名不新建画像，不同应用或租户的账号身份不在本功能中合并。更新、纠正、删除均作用于这个人的共用画像，画像队列也按人串行化。

聊天历史与助手自我视角仍按原聊天范围保留。旧版分域记忆文件不删除、不盲目合并；正式 agent 模式不再把旧版用户条目作为画像读取，避免已删除的新画像又从旧文件复活。旧文件的哈希不能直接反推出用户 ID，因此本次不冒认归属后批量迁移。automatic 评测兼容模式仍可在原聊天读取旧用户条目。新画像使用 user- 前缀文件，原先的裸哈希文件保留供有归属依据的后续迁移。
