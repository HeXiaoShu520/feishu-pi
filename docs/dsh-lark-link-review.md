# dsh-lark-link 调研总结

项目地址：https://github.com/amlyczz/dsh-lark-link

## 核心设计亮点

### 1. 消息零丢失（Outbox 持久化）★★★★★

**价值**：进程崩溃、重启不丢消息

实现要点：
- 出站消息持久化到 JSONL 文件
- at-least-once 投递 + 幂等键
- 分航道并行（每个会话独立队列，互不阻塞）
- 失败消息离队重试（不卡住整个会话）
- 重启自动恢复未发送消息

**是否需要**：
- ✅ 高价值，feishu-pi 当前无持久化
- ⚠️ 但 Pi Agent 本身有会话持久化，消息已在 session 中
- 💡 可简化：只持久化"待发送"的飞书消息，而非全部

### 2. 入站请求补发（Inbound WAL）★★★★

**价值**：Agent 处理到一半崩溃，重启后自动重试

实现要点：
- 入站消息记录到 WAL
- Agent 开始处理前标记，完成后清除
- 重启时检查 WAL，重新触发未完成的消息

**是否需要**：
- ⚠️ Pi 的会话机制已经处理了大部分场景
- 💡 可考虑轻量版：只记录"正在处理"的消息 ID

### 3. CardKit 2.0 流式卡片★★★★★

**价值**：飞书中实时显示 Agent 输出（打字机效果）

官方流程：
```
1. POST /cardkit/v1/cards 创建卡片实体（streaming_mode: true）
2. 发送消息引用 card_id
3. PUT /cards/:id/elements/:element_id/content 流式更新（全量文本）
4. PATCH /cards/:id/settings 关闭流式
5. PUT /cards/:id 最终内容
```

关键点：
- `sequence` 必须严格递增
- 流式更新发送的是**累积全量文本**，不是 delta
- 失败降级到普通文本消息

**是否需要**：
- ✅ 高价值，当前 feishu-pi 只有最终回复
- ✅ 立即可实现（已有回复层）

### 4. 连接自愈★★★★

**价值**：网络抖动、飞书服务端问题自动恢复

实现要点：
- probe 心跳（30s REST 调用测活）
- 静默检测：健康时不重连
- QuotaGovernor：配额熔断（60min/12 次失败）
- 断连补偿：重连后拉取遗漏消息

**是否需要**：
- ✅ 必要，当前靠 SDK 自动重连，不够可控
- ⚠️ 配额熔断需要持久化状态

### 5. 多媒体附件★★★★

**价值**：支持图片识别、文件处理

实现：
- 图片 → 下载 → 视觉模型（Pi 支持 vision）
- 文件 → 文本提取（有界大小）
- 本地持久化 + 定期清理

**是否需要**：
- ✅ 高价值，扩展 Agent 能力
- 💡 先支持图片，文件后续

### 6. 命令分流★★★

**价值**：桥命令、Agent 命令分离处理

三级分流：
```
桥特有命令（/status /doctor）→ 桥处理
注册命令 → 原生执行
其他消息 → 注入 Agent
```

**是否需要**：
- ✅ 必要，当前没有桥命令
- 💡 `/status` `/doctor` 很实用

### 7. 诊断工具★★★

`/doctor` 命令：
- session log
- 配置（脱敏）
- ISSUE 模板
- 打包成 ZIP 回传飞书

**是否需要**：
- ✅ 实用，便于远程排查问题

### 8. 会话管理★★★★

每个飞书会话 = 独立 Agent：
- sessionId ↔ conversationKey 映射
- 持久化到 KV 存储
- 空闲超时回收
- 重启恢复

**是否需要**：
- ✅ 已实现类似机制
- 💡 可优化空闲回收

## 架构分层（值得借鉴）

```
host       → 认证、生命周期
inbound    → 飞书协议（不依赖 Pi）
sessions   → Pi 编排（不依赖飞书）
outbound   → 持久化、发送（sender 注入）
application → 业务逻辑（依赖倒置）
```

**依赖原则**：
- 飞书层 不许 import Pi
- Pi 层 不许 import 飞书
- 通过接口注入通信

## 立即可做的改进

### 优先级 P0（立即实现）

1. **CardKit 流式卡片** - 用户体验提升明显
2. **图片附件支持** - 扩展 Agent 能力
3. **`/status` 命令** - 查看连接状态、会话数

### 优先级 P1（近期）

4. **连接自愈** - probe 心跳 + 受控重连
5. **Outbox 持久化**（简化版）- 只持久化待发送消息
6. **`/doctor` 诊断** - 便于排查问题

### 优先级 P2（后续）

7. **文件附件** - 文本提取
8. **Inbound WAL**（简化版）- 记录处理中的消息
9. **配额熔断** - 防止 API 限流

## 不需要的部分

- ❌ daemon 进程（Pi 本身已是常驻）
- ❌ 复杂的审批流程（当前设计已足够）
- ❌ 多宿主锁（单实例部署）
