# 群聊旁听与成员印象：预留设计

状态：方案预留，尚未实现或启用。记录于2026-11-15。本次仅增加开发文档，不扩大消息采集范围、不拉取历史、不新增后台模型调用，也不修改现有会话和权限隔离。

## 目的

让大肥鱼理解当前群聊的现场：谁在回应谁、当前梗的来源、话题是否已经结束，并从长期交流中逐渐认识具体成员。能够旁听不代表必须发言；知道一个人的聊天习惯不等于与他已经亲近。

现有 `GroupActivity` 只保存每群最近20条短文本、展示名和活动时间，主要供主动发言使用；它没有稳定成员标识、证据链或成员印象存储。现有 `MemoryService` 主要整理与当前说话人的直接交流，不能把旁听消息直接冒充为一次机器人参与的对话。

## 三种资料分别处理

| 资料 | 内容 | 使用方式 |
|---|---|---|
| 当前群聊现场 | 最近发言、时间、回复关系、话题变化 | 有界内存缓冲，正常回应时按相关性注入；不每轮发送全群历史 |
| 群内共同事件 | 群里实际讨论过的事情、参与者、未完话题 | 单独的群范围记忆，注明来源与说法，不能与私人经历混用 |
| 群内成员印象 | 本人明确信息、多次观察的暂时印象、与机器人直接相处的经历 | 按群和真实用户ID保存，允许更正、过期和删除，不自动进入私聊或其他群 |

## 身份与证据

成员主键为 `(chatId, openId)`，展示名只用于显示；改名不创建新人，同名不合并成员。话题群现场与事件还需绑定 threadId；初版成员印象也按话题隔离，跨话题汇总需另行设计。

印象条目应区分：

- `explicit`：本人明确表达，如称呼、兴趣、相处边界。证据必须来自该成员本人。
- `observed`：多次不同消息中可观察到的习惯，如“近期常聊摄影”；是暂时印象，不是人格定论。初版至少两条独立消息支持，不因重复投递或同一句转发升格。
- `direct`：机器人与该成员真实发生过的交流。必须关联实际送达的机器人回复；旁听别人之间的玩笑不能记作机器人与他一起经历过。

建议字段（未来数据格式，当前没有对应运行时接口）：

```ts
interface MemberImpression {
  chatId: string;
  memberOpenId: string;
  threadId?: string;
  kind: "explicit" | "observed" | "direct";
  topic: string;
  summary: string;
  tentative: boolean;
  evidence: Array<{
    messageId: string;
    speakerOpenId: string;
    quote: string;
    at: number;
    replyToMessageId?: string;
    deliveredBotMessageId?: string;
  }>;
  updatedAt: number;
  expiresAt?: number;
}
```

第三人说“某人脾气不好”不能直接成为某人的事实；引用、转发与反讽需保留归属，无法确认时不提炼。优先记行为、偏好和明确反馈，不推断心理诊断、敏感身份、好感分数或固定性格标签。展示时可说“最近几次他常聊摄影”，不升级为“他就是怎样的人”。

图片只记录实际可见内容；飞书收藏表情没有画面时保持未知。不能从占位符推断情绪、性格或群内关系。

## 未来接入点

1. `src/feishu/lark-transport.ts`：沿用现有身份、群准入与话题范围检查。通过检查后，把允许旁听的群事件交给独立观察入口，不因未触发回复而强制创建 Pi 会话。观察入口按 messageId 去重，并处理编辑、撤回和重复投递；原来的消息 claim 继续只负责响应链路。
2. `src/feishu/group-activity.ts`：增强短期消息结构，补齐发送者 openId、messageId、replyToMessageId、threadId、资源可见性。不能只凭展示名形成成员档案；缓冲仍有数量、文本长度和存活时间限制。
3. 独立的群观察服务：与飞书 SDK、Pi 解耦，由 `main.ts` 装配。按群批次节流，只提炼有价值的信息；先在短期上下文中验证收益，再考虑成员印象持久化，不对每条消息调用模型。
4. 正常回复入口：通过临时请求资料注入相关群现场和当前成员印象，不持久化到个人 Pi 历史；控制总预算，避免每轮带上所有成员档案。
5. `src/memory/service.ts`：继续负责现有直接交流记忆。未来增加旁听资料时必须保留来源类型和范围，不能调用 `observe` 伪造 assistantText 来冒充直接交流，也不能把群事件写进全局自我记忆。

本次不添加空服务、未使用接口、假配置开关或空存储目录。上述结构与接入点是未来实现约定，不代表可运行的能力。

## 范围与生命周期

- 未来显式开启并指定允许观察的群；默认不启动。旁听、持久提炼、主动发言三个开关含义独立，开启旁听不自动提高回复概率。
- 私聊内容不带入群；群印象不自动带入私聊、其他群或其他话题。任何个性化内容都不能改变权限和工具注册。
- “整个群聊”初版指开启后收到的、允许范围内的消息，不自动全量回溯历史；历史补录须单独设计来源和处理预算。
- 候选数据目录为 `data/group-observation/`，尚不存在相应存储约定的实现；不得复用私人记忆文件。各群独立设置条目上限和保留期，先短期后持久化。
- 新证据可更正旧印象，长期没有支持的暂时印象应过期。撤回或删除来源消息后，删除对应证据；证据不足的观察项降级或移除。禁用观察停止收集与提炼，删除群或成员资料应支持可核查的清除范围。

## 实现顺序与验收

先做“可信身份＋回复关系＋短期群现场”，验证能接上梗、区分对谁说话和适时沉默；再加群内事件，最后加逐人印象。避免一开始就构建复杂画像系统。

未来至少验证：同名与改名不串人；不同群/话题/成员/私聊不串资料；重复消息不累加证据；第三人评价不能变成本人事实；转发不归给转发者；旁听不冒充直接相处；编辑撤回使旧证据失效；未取得图片不产生视觉判断；预算有界；关闭时不调用提炼模型；成员印象不能绕过权限；机器人旁听不强制发言。

这是对现有人格和事实记忆的后续扩展，不是自动改写 SYSTEM.md 的人格成长层。
